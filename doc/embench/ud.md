# ud 性能分析

## 1. 源码分析

### 1.1 基本信息
- **源文件**: `thirdparty/embench-iot/src/ud/libud.c`
- **算法描述**: LU 分解求解 6×6 线性方程组（`long` 类型），基于 20×20 稀疏矩阵
- **LOCAL_SCALE_FACTOR**: 1785
- **数据类型**: `long int`（64-bit signed integer）

### 1.2 调用链
```
benchmark() → benchmark_body(lsf=1785, gsf=1)
  └→ 循环 1785×1 = 1785 次（+ warmup 1 次 = 1786 总计）
      ├→ Init: 双重循环 6×6 = 36 次，初始化 a[6][6] 和 b[6]
      └→ ludcmp(nmax=20, n=5)
          ├→ LU 分解: 三角循环 i=0..4
          │   ├→ 第一 j 循环: w = a[j][i] - Σ a[j][k]*a[k][i], a[j][i] = w/a[i][i]
          │   └→ 第二 j 循环: a[i+1][j] = a[i+1][j] - Σ a[i+1][k]*a[k][j]
          ├→ 前向替代: y[i] = b[i] - Σ a[i][j]*y[j]
          └→ 后向替代: x[i] = (y[i] - Σ a[i][j]*x[j]) / a[i][i]
```

### 1.3 核心计算函数

```c
int ludcmp(int nmax, int n) {
  int i, j, k;
  long w, y[100];

  for(i = 0; i < n; i++) {                    // L1: 5 次
    for(j = i+1; j <= n; j++) {                // L2a: 三角递减
      w = a[j][i];
      if(i != 0)
        for(k = 0; k < i; k++)                // L3a: 三角递增 ★热点
          w -= a[j][k] * a[k][i];
      a[j][i] = w / a[i][i];
    }
    for(j = i+1; j <= n; j++) {                // L2b: 三角递减
      w = a[i+1][j];
      for(k = 0; k <= i; k++)                 // L3b: 三角递增 ★最热
        w -= a[i+1][k] * a[k][j];
      a[i+1][j] = w;
    }
  }
  // 前向替代 + 后向替代（结构与 L3 类似）
}
```

### 1.4 循环结构

| 循环层 | 变量 | Trip Count | 说明 |
|--------|------|-----------|------|
| benchmark_body 外层 | lsf_cnt | 1785 | LOCAL_SCALE_FACTOR |
| benchmark_body 内层 | gsf_cnt | 1 | GLOBAL_SCALE_FACTOR |
| Init 外层 | i | 6 (0..5) | 矩阵初始化 |
| Init 内层 | j | 6 (0..5) | 每行填充 |
| L1 | i | 5 (0..4) | LU 分解外层 |
| L2a | j | 5-i (三角) | 第一 j 循环 |
| **L3a** | **k** | **i (三角)** | **LU 累加（第一部分），i=0 时跳过** |
| L2b | j | 5-i (三角) | 第二 j 循环 |
| **L3b** | **k** | **i+1 (三角)** | **LU 累加（第二部分）★最热** |
| 前向替代 | j | i (三角) | y[i] 计算 |
| 后向替代 | j | n-i (三角) | x[i] 计算 |

**内层迭代次数统计**（每次 ludcmp 调用）:
- L3a: Σ(j=i+1..5) i, for i=1..4 = 4+6+6+4 = **20**
- L3b: Σ(j=i+1..5) (i+1), for i=0..4 = 5+8+9+8+5 = **35**
- 前向替代 k 循环: 1+2+3+4+5 = **15**
- 后向替代 k 循环: 1+2+3+4+5 = **15**

### 1.5 访存模式

| 数组 | 大小 | 访问方式 | 说明 |
|------|------|---------|------|
| a[20][20] | 3200B | 行/列混合 | 20×20 但只用 6×6，stride=160B（跨行） |
| b[20] | 160B | 顺序 | 前向替代读取 |
| x[20] | 160B | 逆序 | 后向替代写入 |
| y[100] | 800B | 栈上 | 前向/后向替代临时数组 |

**数据总量**: ~4.3KB → **完全驻 L1D**

### 1.6 计算特征

- **计算密集型**: 数据全在 L1，瓶颈在 MUL/DIV 吞吐和依赖链
- **运算类型**: 整数乘法 (`mul`) + 整数减法 (`sub`) + 整数除法 (`div`)
- **分支**: 多层三角循环控制，trip count 小（1~5），高度可预测
- **特殊**: 包含整数除法 `div`（延迟极高，~20-60 cycles），每次 L2 迭代尾部都有一次

### 2.4 内层循环微架构分析

**L3b 指令混合** (7 条/iter，最热循环):
- ld: 2 (28.6%)
- addi: 2 (28.6%)
- mul: 1 (14.3%)
- sub: 1 (14.3%)
- bne: 1 (14.3%)

**关键依赖链 (L3b)**:
```
ld a4 ──┐
         ├→ mul a4,a4,a0 → sub a2,a2,a4
ld a0 ──┘
```
延迟: ld(2) + mul(3~4) + sub(1) = 6~7 cycles

**循环携带依赖**:
- `a2` (=w): 累加器，`sub a2,a2,a4` → 下次 `sub` 的输入 → RAW 1-cycle
- `a5`/`a3`: 地址指针，`addi` 1-cycle，不是瓶颈

**DIV 瓶颈**:
- 每次 L2a 迭代结束有一次 `div`（~20-60 cycles），但在循环外部
- LU 分解中 div 总次数/调用: L2a 有 Σ(i=0..4)(5-i) = 15 次，前/后向各 5+6 = 11 次
- 每次 ludcmp 调用约 15+5+6 = 26 次 div

**预计 IPC (OoO core)**:
- 内层循环: 7 条 / 6~7 cycles ≈ 1.0~1.17
- 两个 ld 可并行发射，两个 addi 可并行
- mul→sub 串行链限制 IPC 上界
- div 指令在循环外但延迟极高，可能成为整体瓶颈

## 3. 总结

```
算法:           LU 分解求解 6×6 线性方程组 (long)
数据量:         ~4.3KB (20×20 矩阵 + 向量, 全驻 L1D)
计算类型:       int ld/mul/sub 密集 + div (循环尾部)
内层循环指令数: 7 条 (4 个同构循环)
内层循环占比:   L3b 15.5% + L3a 8.8% + 前/后向 13.2% + Init 13.7% = ~51.2%
瓶颈预测:       compute-bound (mul→sub 依赖链 6~7c, div ~20-60c 在循环外)
分支特征:       多层三角循环, trip count 极小 (1~5), 高度可预测
特殊:           整数 div 频繁出现 (每次 ludcmp 调用 ~26 次)
```
